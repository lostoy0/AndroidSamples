# Flutter 引擎启动与页面首帧实测

同一个全屏 Flutter 详情页中，进程内首次创建 Group 并启动首个引擎的同步耗时中位数为 **16.2 ms**，占路由到首帧时间的 **4.8%**。Group 内有存活引擎时，全屏 Activity 仍创建独立引擎，路由到首帧的中位数从 Group 为空时的 **313.1 ms** 降至 **44.0 ms**。两组同步引擎调用的中位数相差 **2.1 ms**。

## 实测结果

2026-11-20 在 Apple M4 Pro 上的 Pixel 9 Pro 模拟器测试，使用 Android 16（API 36）、`arm64-v8a`、Flutter 3.44.7 和 Release AOT APK。每组采集 20 个样本，另有 2 轮预跑。三组均从原生首页打开同一个全屏 Flutter 详情页，路由为 `samples://flutter/detail/42?title=Flutter`。

| 场景 | 创建 Group（ms） | 创建并启动引擎（ms） | 路由到 Flutter 首帧（ms） | 引擎调用占比 |
| --- | ---: | ---: | ---: | ---: |
| 进程内首次打开 Flutter，创建 Group 和首个引擎 | 2.9 / 3.6 | 13.0 / 23.8 | 335.1 / 361.8 | 3.8% |
| 同一进程再次打开，Group 仍在且引擎数为零 | 复用 | 4.2 / 4.7 | 313.1 / 330.6 | 1.3% |
| 同一进程再次打开，隐藏的 Flutter Tab 引擎仍存活 | 复用 | 2.1 / 3.0 | 44.0 / 53.7 | 4.8% |

耗时列为「中位数 / P90」。占比先在单次样本内用引擎调用耗时除以路由到首帧耗时，再取中位数。

- **Group 创建**从调用 `FlutterEngineGroup(applicationContext)` 到构造完成。进程内首次打开时，Group 与引擎两段同步耗时合计中位数为 **16.2 ms**，占到首帧时间的 **4.8%**。
- **引擎创建并启动**从进入 `FlutterEngineGroup.createAndRunEngine(options)` 到返回，每次全屏 Activity 都获得一个新的引擎。Group 为空时重新初始化引擎，有存活引擎时从它派生新引擎。
- **路由到首帧**从进入 Android 路由函数到 Activity 收到首次 `onFlutterUiDisplayed()`。它包含 Activity 调度、宿主和渲染表面接入、异步 Dart 启动和首帧绘制。方法返回到首帧的中位数依次为 **311.1 / 275.4 / 34.8 ms**。现有测量无法把这段再分摊到各项工作。

对这条路径，Group 为空和有存活引擎的两组，首帧中位数相差 **269.1 ms**。其中同步创建方法的中位数相差 **2.1 ms**。这组数据可以评估保留存活引擎对当前页面的收益，具体毫秒数会随设备、Flutter 页面与构建类型变化。

测试用临时副本添加计时与路由触发入口。每轮先停止测试进程，启动原生首页后采集首个引擎。关闭全屏容器并确认引擎数归零后采集第二次。随后打开 Flutter Tab，等其首帧，再切回原生 Tab 保留引擎并采集第三次。计时采用 Android 单调时钟 `SystemClock.elapsedRealtimeNanos()`。模拟器结果不包含启动原生进程的时间，首帧终点使用 Flutter 回调。
